# 0.5.1 — Records and disputed questions

This release implemented M0 of the optimization plan, protecting the evidence used by later scheduling and knowledge-point work.

## Changes

- Report a question from the question, feedback, or history view and invalidate it with a reason. Matching copies from the same material revision are excluded together. Original answers and assessments remain, and invalidation can be undone.
- Invalidated questions no longer influence progress, learning state, model evidence, or review scheduling. Questions invalidated before answering remain in history after being replaced.
- Evidence from different material revisions or excerpts is no longer merged into a stable status. Punctuation and whitespace changes do not make a question new; gaps require new evidence before stability returns.
- Choice drafts and confidence save before submission. Late drafts from older sessions cannot overwrite new sessions. Unloaded instances reject new submissions and restore operations.
- Empty notes do not replace the current session. Zero-byte notes are excluded from new courses. Moved or deleted source notes offer a refresh path.
- Data format 2 reads older data, saves one pre-upgrade snapshot, and rejects fallback to an old backup when data comes from a future version.

## Validation

Evidence and session tests cover source-version isolation, invalidated duplicates, fast selection/submission, double submissions, and late drafts. The smoke script and legacy fixture cover settings/draft migration, damaged backups, and future-format rejection. Obsidian flows cover mobile-sized reporting, reload/undo, empty material, and moved notes.

Passed at the time: 55 automated tests, 15 isolated real-Obsidian flows with mobile emulation, type checks, build, bundle loading, migration/recovery, and package checks. Fixtures used synthetic material and credentials, not the user's real model. This is regression evidence, not a learning-outcome or question-quality evaluation.

## Upgrade and rollback

Update the three runtime files. The first read of older data retains `data.pre-0.5.1.json`; courses, drafts, settings, and history remain. Normal saves use format 2 and keep the previous complete backup.

Before downgrading, disable the plugin and privately back up current data files. Restore the pre-upgrade snapshot together with the matching old runtime. New answers and invalidation records are absent from the old snapshot. These data files may contain unencrypted keys.

## Limitations at this version

Course status was still aggregated by note. Stable knowledge-point profiles were not implemented. Text normalization only catches simple repeats. Old review copies without origin IDs match on saved content and source revision, so rewritten copies cannot always be recognized.

Exported Markdown is a snapshot and is not automatically rewritten after invalidation. Reporting a question excludes it from calculations; it does not prove the system verified an error. Course question-type configuration was still planned for M1. iOS and Android devices had not been tested.
